Feature Specification: System Prompt Bank

Overview
The System Prompt Bank is a lightweight PHP-based mobile-responsive web application that allows users to store, manage, categorize, and version reusable system prompts. It is designed as a Single Page Application (SPA) using TailwindCSS, ES6 JavaScript, and SQLite for persistence.

Core Features

1. User Authentication
   - Login Screen: Secure login interface with credentials validated against SQLite database
   - Session-based authentication using PHP sessions
   - Logout functionality to safely destroy active session

2. Dashboard (Single Page Application)
   - Single-page interface accessible after login
   - All main features available without full-page reloads
   - Dynamic content updates via JavaScript

3. Prompt Management

   a. Add New System Prompt
      - Form fields:
        * Title (string, required)
        * Category (dropdown or tag input)
        * System Prompt Text (multi-line input, supports markdown, required)
      - On save:
        * Stored in SQLite prompts table
        * Creates initial version record in prompt_versions table
        * Auto-refreshes prompt list via JavaScript fetch/AJAX

   b. View Saved Prompts
      - Searchable, sortable list displaying:
        * Title
        * Category
        * Short preview
        * Creation date
        * Last updated date
      - Supports:
        * Sorting (by title, date, category)
        * Filtering (by category/tag)
        * Client-side search

   c. View Prompt Details
      - Full content display with metadata (category, creation/update time)
      - Version History tab showing all past changes
      - Diff-style comparison (similar to GitHub's green/red code comparison)
      - Each version entry includes:
        * Version number
        * Edited by user
        * Date/time of edit
        * View diff button

   d. Edit or Delete Prompts
      - Editing creates new version entry with content diff
      - Soft delete (archive) functionality
      - Delete confirmation modal

4. Prompt Versioning
   - Every edit creates new entry in prompt_versions table
   - Preserves prior content with version tracking
   - Visual diff view options:
     * Inline color highlighting (added/removed text)
     * Split view (side-by-side comparison)

5. Prompt Categorization
   - Organize prompts into categories
   - Category options:
     * Predefined categories (System Setup, Debugging, Creative Writing)
     * User-defined categories via management UI

UI/UX Guidelines

- Responsive design for desktop, mobile, and tablet

Database Schema

Table: users
Field       Type                        Description
id          INTEGER (PK, Auto Increment) Unique user ID
username    TEXT                        Login username
password    TEXT                        Hashed password

Table: prompts
Field         Type                        Description
id            INTEGER (PK, Auto Increment) Unique prompt ID
title         TEXT                        Prompt title
content       TEXT                        Current version content
category_id   INTEGER                     Foreign key to categories.id
created_at    DATETIME                    Creation timestamp
updated_at    DATETIME                    Last update timestamp
is_archived   BOOLEAN                     Soft delete flag (default: false)

Table: prompt_versions
Field            Type                        Description
id               INTEGER (PK, Auto Increment) Unique version ID
prompt_id        INTEGER                     Foreign key to prompts.id
version_number   INTEGER                     Sequential version count
content          TEXT                        Versioned prompt text
created_at       DATETIME                    Timestamp of version creation
user_id          INTEGER                     Foreign key to users.id

Table: categories
Field       Type                        Description
id          INTEGER (PK, Auto Increment) Unique category ID
name        TEXT                        Category name
is_system   BOOLEAN                     System-defined category flag

Security Considerations
- Passwords stored using PHP's password_hash() and verified with password_verify()
- Session-based access control for all CRUD routes
- Input validation and sanitization for user data
- CSRF protection for form submissions
- SQL injection prevention using prepared statements
